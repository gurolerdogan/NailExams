## Key facts (established in the cloud session)

- **Node:** Expo SDK 54 needs Node **≥ 20.19.4**. Target `20.19.5` via nvm-windows.
  Use the stable 1.x release from `github.com/coreybutler/nvm-windows/releases` (`nvm-setup.exe`);
  `github.com/nvm-windows/nvm/releases` only showed 2.1.0 **pre-releases**.
- **Repo has a `.nvmc` file** (typo of `.nvmrc`, contains `20`) — nvm-windows ignores it anyway.
- **Line endings:** `.editorconfig` enforces LF → git should use `core.autocrlf input`, `core.eol lf`.
- **Branches:** `CLAUDE.md` says work on `develop`. `origin/main` (`4f9efe1` chore: release v1.7.0)
  was one commit ahead of `origin/develop` (`611cef7`) → fast-forward `develop` to `main`.
- **Env files:** there is **no `.env`**. The old machine used `.env.development` and `.env.production`
  (copied over). Expo CLI auto-loads `.env.<NODE_ENV>` (`expo start` / `expo run:*` → development).
  `app.config.ts` also does `import 'dotenv/config'` (plain `.env`) — harmless if absent.
  Both files are gitignored via `.env.*` — they must never be committed.
- **EAS cloud builds don't see the env files** (gitignored → not uploaded). `eas.json` only sets
  `APP_ENV` + `GOOGLE_*_CLIENT_ID`, so `FIREBASE_*` for cloud builds must come from **EAS environment
  variables** on expo.dev — verify with `eas env:list`.
- `google-services.json` and `GoogleService-Info.plist` are committed in the repo.
- `/ios` and `/android` are gitignored (generated by `expo run:*` / prebuild).
- **iOS cannot be built locally on Windows** → use `eas build -p ios`. Android can be local or EAS.
